# پیش‌بینی وضعیت ترافیک با شبکه‌های LSTM

این پروژه استفاده از شبکه‌های عصبی بازگشتی مبتنی بر LSTM را برای پیش‌بینی وضعیت بعدی ترافیک (طول صف‌ها / پیکربندی فاز چراغ) در شبکه‌ای از تقاطع‌ها بررسی می‌کند؛ قدمی به سمت کنترل تطبیقی چراغ راهنمایی.

ایده این است: به‌جای یک برنامه زمانی ثابت برای چراغ راهنمایی، یک شبکه می‌تواند پیش‌بینی کند ترافیک قرار است چطور تغییر کند و از پیش خودش را تنظیم کند. این ریپو پیش‌پردازش داده، تعریف مدل‌ها و آزمایش‌هایی را دارد که برای آزمودن چند روش مختلف برای صورت‌بندی مسئله پیش‌بینی استفاده شدند.

> پروژه درسی **هوش مصنوعی**، بهار ۲۰۲۱.
> نویسنده: محمد عباسی‌شاهکوه · استاد: دکتر فرناز ماهان

## صورت‌بندی مسئله

هر نمونه در دیتاست یک ردیف است که وضعیت ترافیک یک تقاطع را در یک لحظه زمانی توصیف می‌کند. دیتاست دنباله‌ای از این ردیف‌هاست (مرتب زمانی)، پس مسئله به‌طور طبیعی به‌صورت پیش‌بینی دنباله صورت‌بندی می‌شود و با LSTM مدل می‌شود.

سه روش برای صورت‌بندی جفت ورودی/هدف امتحان شد:

- **نوع ۱ — فقط وضعیت.** ورودی: پنجره‌ای از `n` وضعیت متوالی (ستون‌های ۰ تا ۷). هدف: وضعیت در `n+1`. رگرسیون ساده قدم بعدی.
- **نوع ۲ — وضعیت + عمل (کدگذاری‌شده).** ورودی: پنجره‌ای از ستون‌های وضعیت همراه با ستون‌های عمل متناظر (۴ ستون آخر داده خام)، که تاپل عمل به یک شناسه عددی واحد کدگذاری شده. هدف: فقط وضعیت بعدی.
- **نوع ۳ — وضعیت + عمل، پیش‌بینی هر دو.** همان کدگذاری نوع ۲، ولی شبکه آموزش می‌بیند که هم وضعیت بعدی *و* هم عمل بعدی را پیش‌بینی کند. یک اسکریپت جدا (`traffic_lstm_classification.py`) بخش عمل این صورت‌بندی را به‌عنوان یک مسئله دسته‌بندی چندکلاسه (خروجی one-hot / softmax) در نظر می‌گیرد، نه رگرسیون.

همه ورودی‌های عددی قبل از آموزش با `MinMaxScaler` به بازه `[0, 1]` مقیاس می‌شوند و پیش‌بینی‌ها برای گزارش RMSE به مقیاس اصلی برمی‌گردند.

## مدل‌ها

دو معماری کوچک LSTM روی‌هم‌چیده برای واریانت‌های رگرسیون (نوع ۱ / نوع ۲) و یک پشته LSTM + dense کمی عمیق‌تر با سر softmax برای واریانت دسته‌بندی (نوع ۳) استفاده شد.

| | مدل رگرسیون (نوع ۱ / ۲) | مدل دسته‌بندی (نوع ۳) |
|---|---|---|
| لایه ۱ | LSTM(6), sigmoid | LSTM(6), tanh |
| لایه ۲ | LSTM(6), sigmoid | LSTM(6), tanh |
| لایه ۳ | Dense(n_features) | Dense(10), tanh |
| لایه ۴ | — | Dense(10), tanh |
| لایه ۵ | — | Dense(8), tanh |
| خروجی | — | Dense(n_classes), softmax |
| تابع خطا | MSE | Categorical cross-entropy |
| بهینه‌ساز | Adam | Adam (lr=0.04) |

آموزش با `EarlyStopping` (پایش خطا) و `ModelCheckpoint` (ذخیره بهترین مدل بر اساس خطای اعتبارسنجی)، اندازه بچ ۳۲ و اندازه پنجره ۵ و ۱۰ گام زمانی انجام شد.

### برداشت‌ها

- اندازه پنجره (۵ در برابر ۱۰) تفاوت زیادی برای این دیتاست نداشت — شبکه در هر دو حالت به خطای تقریبا یکسانی همگرا می‌شود و خطای آموزش بعد از چند epoch صاف می‌شود (به همین دلیل early stopping در چند اجرا زود فعال شد).
- صورت‌بندی‌های رگرسیون (نوع ۱/۲، پیش‌بینی وضعیت بعدی) نسبتا خوب کار کردند. صورت‌بندی دسته‌بندی (نوع ۳، پیش‌بینی عمل گسسته بعدی از فضای عمل کدگذاری‌شده) به‌وضوح ضعیف‌تر عمل کرد — کدگذاری فضای عمل پرتعداد است و کلاس‌ها نامتوازن‌اند، که عددهای دقت هم نشان می‌دهند.
- یک اجرا با پنجره ۳۰ روی دیتاست ۱ بهبود معناداری نسبت به ۵/۱۰ نشان نداد، ولی اندازه‌های پنجره بزرگ‌تر به دلیل محدودیت سخت‌افزار بیشتر بررسی نشدند.

## ساختار ریپو

```
.
├── src/
│   ├── traffic_lstm_regression.py      # صورت‌بندی نوع ۱ و ۲، رگرسیون وضعیت بعدی
```

## داده

داده خام مجموعه‌ای از فایل‌های CSV است (یکی برای هر منبع داده) بدون سرستون، که ستون‌های ۰ تا ۷ وضعیت ترافیک و ۴ ستون آخر پیکربندی عمل/فاز چراغ را توصیف می‌کنند. اسکریپت‌ها انتظار دارند همه فایل‌های CSV یک دیتاست در یک پوشه باشند و صرفا آن‌ها را به ترتیب نام فایل به‌هم می‌چسبانند — نگاه کنید به `read_dataset()` در هر اسکریپت.

دیتاست در این ریپو نیست. متغیر `DIR_PATH` در بخش پیکربندی بالای هر اسکریپت را به کپی لوکال خودتان اشاره دهید.

## اجرا

```bash
pip install -r requirements.txt
python src/traffic_lstm_regression.py
python src/traffic_lstm_classification.py
```

هر دو اسکریپت نزدیک بالا یک بلاک پیکربندی کوچک دارند (مسیر دیتاست، `TYPE` مسئله، اندازه پنجره، اندازه بچ، epoch) — راحت‌ترین راه برای جابه‌جا شدن بین آزمایش‌ها بدون دست زدن به بقیه کد.

## پیشینه / مطالعه مرتبط

این پروژه بعد از خواندن درباره رویکردهای تطبیقی و یادگیرنده برای کنترل چراغ راهنمایی نوشته شد، به‌ویژه:
